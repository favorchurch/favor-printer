# Windows Favor Printer — local acceptance and release gate

**Tracking:** [Favor Printer #42](https://github.com/favorchurch/favor-printer/issues/42), [draft Favor Printer PR #75](https://github.com/favorchurch/favor-printer/pull/75), and [draft RSVP canonical relay PR #1002](https://github.com/favorchurch/rsvp.favor.church/pull/1002). These draft PRs are not production approval.

**Architecture:** RSVP web remains the only check-in controller. Favor Printer for Windows is *only* a relay host. The existing cloud queue, campus, printer UUID, OTP and label contracts are reused. Mac CUPS remains unchanged; Windows uses an existing USB ZPL printer in the Windows Print Spooler with the pinned RAW helper sourced from RSVP.

## Before touching a production printer

Use an authorized **Windows 10/11 x64** PC and an **approved Zebra USB ZPL printer (ZD421 priority)**. Obtain the official Zebra ZDesigner ZPL driver from the authorized IT distribution; do not install unknown drivers or lower enterprise PowerShell execution policy. Use test / nonproduction RSVP credentials, an approved campus/test printer and label stock. Never publish printer serials, tokens, enrollment codes, names or attendee label contents in issue logs or screenshots.

1. Check out the **existing PR #75 branch** and read `AGENTS.md`, this guide, `docs/WINDOWS-DISCOVERY.md` and `docs/WINDOWS-RAW-TRANSPORT.md`. Confirm the branch head before and after local fixes. Keep canonical shared relay changes in RSVP `relay/` and vendor them only through its official sync script. Do not edit `vendor/relay` by hand.
2. Install Node >=22.13, pnpm 10 through Corepack. Run `pnpm install --frozen-lockfile`, `pnpm verify:vendor`, `pnpm lint`, `pnpm typecheck`, `pnpm test`, and `pnpm build`. Run `pnpm exec electron-builder --win nsis --x64 --publish never` for an **unsigned** local NSIS validation artifact. Before any production use, have the authorized owner sign and verify the installer / update channel. **Do not label unsigned artifacts production-ready.**
3. Install the approved ZDesigner ZPL driver and USB Zebra. In normal Windows PowerShell (no execution-policy bypass), run `./scripts/windows/probe-printers.ps1` from the cloned repo, or the packaged trusted helper. Confirm that the selected local queue, expected USB connection and **verified unique Zebra hardware serial** agree under unplug/replug and queue renaming. The probe returns a versioned `Win32_Printer` JSON report with private device data: sanitize it before sharing. `USB001`, `USBPRINT` instance suffixes, SWD/PRINTENUM, and display names are not hardware serials. When unique USB parent evidence is unavailable, enrollment **must remain blocked**, and the device/driver path needs a reviewed fix—not a guessed serial or manual cloud UUID.
4. Launch the Windows app from the installer as a standard user. Confirm setup selection, Windows Printers & scanners deep link, host-friendly name and per-user credential encryption through Electron safeStorage. Use a fresh **test** RSVP OTP; verify cloud records reflect the correct existing/new canonical printer identity and campus. Re-enroll or move a printer between hosts only after authorized handover; compare cloud registry before/after for duplicates.
5. Print a cloud-routed test label, then **both parent and child** labels from non-production RSVP `/checkin`. Check real printed template content, counts, ordering and pickup associations; do not include private label content in screenshots. An OS spooler `sent` receipt alone is not evidence that paper printed. Confirm a single selected cloud printer UUID goes to a single local USB queue.
6. Test unplug during idle and during send, replug, Wi-Fi offline/backlog, sleep/resume, printer power off/on, queue rename/reassignment, different Zebra on the same USB port, app crash/restart, host enrollment/revocation and authorized reassignment. The relay must never print to the newly attached **different hardware serial**, never revive a revoked token and **never auto-replay `sending`/`ambiguous` jobs**. The operator must reconcile uncertain paper outcomes manually.
7. Validate Windows installer install/update/restart/uninstall/re-enroll, startup at login, Windows Security / endpoint protection, PowerShell policy, uninstall of credential state, and physical Zebra acceptance. Regression-test Mac pairing and CUPS on an available Mac or through independent CI. Record exact PR heads and sanitized tests/evidence, then request independent review before making a PR ready/merging.

## Remote versus hands-on completion

- **Remote-implemented for review:** Windows service and fixed-script wiring; verified-USB-serial fail-closed discovery; cloud OTP and protected pairing; queue safety; PowerShell RAW transport from RSVP; Windows setup copy and unsigned installer configuration; unit tests and build.
- **Not verified without the real Windows PC:** PowerShell PnP properties and actual serial on the target Zebra/driver, Winspool P/Invoke and physical label printing, endpoint protection, real Windows installer and code signing, update/re-enrollment and end-to-end campus safety. A Linux cross-build is not Windows hardware acceptance.
- **Release gate:** Keep both PRs draft and issue #42 open until these physical, hosted CI, independent-review and signing gates have evidence. Do not touch production enrollment or release without explicit authorization.
